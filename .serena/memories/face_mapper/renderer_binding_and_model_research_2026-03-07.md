Investigated the Unity face mapper pipeline for the ThirdPersonController character. Key findings: (1) PlayerFaceMapper runtime only swaps one material slot on Ch33_Body, so networking/material assignment were not the primary issue. (2) PlayerArmature 1 1 prefab contains two model roots: an inactive local Ch33_nonPBR copy and an active nested prefab instance named Ch33_nonPBR (1). Existing renderer discovery in both PlayerFaceMapper.FindBodyRenderer and FaceMapperEditorTool.FindBodyRenderer used GetComponentsInChildren(..., true) and returned the first body renderer, which could bind to the inactive mesh. (3) Patched runtime resolver to prefer active-in-hierarchy body renderers and recover from stale serialized renderer references. Patched editor setup discovery to prefer active body renderers within prefab assets. (4) Remaining quality-sensitive model assumptions in FaceMapperEditorTool: static FaceUVRect=(0.716,0.744,0.285,0.264), canonical processed portrait input with no recrop, stretch-to-fill from square portrait to wider UV island, bone-weight-based face triangle extraction using head/neck/jaw/face/eye bones, and geometry fallback thresholds for centroid/normal orientation. (5) Research still needed for photo fidelity: validate actual frontal face UV island against FaceUVRect, confirm nested prefab active body mesh is the same mesh used for bake source, inspect how much non-face skin is influenced by neck/head bones, verify seam placement around ears/jaw/neck, and characterize how canonical landmark alignment maps onto this character’s stylized proportions and skin shading.
