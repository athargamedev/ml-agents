Validated Faceit addon workflow in Blender 5.0 against the opened character FBX meshes. Faceit addon key is bl_ext.user_default.faceit. Live scene had Ch33_Body and Ch33_Eyelashes skinned to Armature.002, and model_T skinned to Armature. Ch33 character can be registered in Faceit via faceit.add_facial_part; Faceit auto-populates scene.faceit_body_armature=Armature.002. Initial scene had no Faceit armature, no face objects, and no generated shapes. Faceit is a facial rigging/binding/retargeting tool (landmarks, smart bind, ARKit/A2F/FBX retargeting), not a photo-to-likeness generator. For Ch33_Body, a usable faceit_main vertex group can be derived automatically by summing bone weights from names containing head/neck/jaw/eye/face, filtering to frontal head-space vertices, then keeping only the largest connected component. Validated connected-component sizes for the first candidate region were [3593, 449, 449, 74, 60]; keeping the largest component removed Faceit MAIN_GROUP warnings. Faceit warning checks also require the source armature to be in REST pose before landmarks/binding; switching Armature.002 from POSE to REST cleared remaining ARMATURE_POSITION warnings for Ch33_Body and Ch33_Eyelashes. Faceit facial_landmarks operator requires a real VIEW_3D context override when called from scripting; calling bpy.ops.faceit.facial_landmarks('EXEC_DEFAULT') with temp_override(window, area=VIEW_3D, region=WINDOW) successfully created facial_landmarks with state=0 and message 'Align the Landmarks with your characters chin!'. Added reusable repo script Tools/blender/faceit_auto_prep.py to automate Faceit registration, armature inference, faceit_main creation, rest-pose switching, landmark initialization, and warning collection. Added docs/Faceit-Custom-Face-Pipeline.md documenting the split: use Faceit once per base FBX for rig/shape-key prep, and keep player-photo customization as a separate texture-generation pipeline that can feed the existing Unity FaceMapperEditorTool/PlayerFaceMapper runtime.
